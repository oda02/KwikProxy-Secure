# Политика конфиденциальности KwikProxy Secure

**Дата обновления:** 2026-08-30

KwikProxy Secure — это VPN-клиент с открытым исходным кодом, разработанный
с принципом *zero-telemetry*. Этот документ объясняет, какие данные
приложение обрабатывает, где они хранятся и кому передаются.

## Краткая версия

KwikProxy Secure **не собирает, не передаёт и не хранит** на сторонних серверах
никаких данных о пользователе или его активности. Всё, что приложение
читает или пишет, остаётся на вашем компьютере. У нас нет аналитики,
телеметрии, отчётов о крашах, A/B-тестов и прочих механизмов сбора
информации.

## Что приложение делает на вашем компьютере

### 1. Локальные файлы и хранилища

| Что | Где | Зачем |
|---|---|---|
| Серверы подписки | `%LOCALAPPDATA%\KwikProxy Secure\subscription-cache\*.dpapi` | Sanitized профиль и секреты нод шифруются Windows DPAPI для текущего пользователя; plaintext в WebView/localStorage не записывается |
| Настройки UI | `localStorage` встроенного WebView2 | Тема, язык, режимы подключения, правила per-app |
| URL подписки и HWID-override | Windows Credential Manager, отдельные записи для каждой подписки | Защищённое хранилище ОС |
| Backup настроек | `Documents\kwikproxy-secure-backup-<timestamp>.json` только по кнопке экспорта | URL/token подписки по умолчанию отсутствует; его можно включить только отдельным opt-in с предупреждением |
| Routing-профили | `%LOCALAPPDATA%\KwikProxy Secure\routing\*.json` | Кеш правил маршрутизации |
| Geofiles (`geoip.dat`/`geosite.dat`) | `%LOCALAPPDATA%\KwikProxy Secure\geofiles\` | Базы IP-адресов и доменов для split-routing |
| Резервная копия системного прокси | `%LOCALAPPDATA%\KwikProxy Secure\proxy_backup.json` | Чтобы вернуть оригинальные настройки прокси при отключении |
| Лог приложения, `mihomo-stderr.log` | `%TEMP%\KwikProxy Secure\` | Локальная диагностика |
| `helper.log`, `mihomo.log` (TUN-режим) | `C:\ProgramData\KwikProxy Secure\` | Лог SYSTEM-сервиса: решения kill switch, работа TUN |
| Crash-dump (если случилась паника) | `%LOCALAPPDATA%\KwikProxy Secure\crashes\<timestamp>.txt` | Чтобы при следующем старте приложение могло предложить вам выгрузить диагностику |

Никакие из этих файлов не покидают ваш компьютер. Если вы захотите
поделиться диагностикой с поддержкой, в Settings есть кнопка
**«выгрузить диагностику»** — она соберёт zip-архив, который вы можете
отправить вручную (или не отправить).

> Локальный лог Mihomo может содержать адреса соединений (домены/IP) —
> это нужно для диагностики «почему сайт не открылся». Лог хранится
> только на вашем диске, никуда не отправляется и попадает в
> диагностический архив только когда вы сами его выгружаете.

### 2. Сетевые запросы, которые делает приложение

KwikProxy Secure обращается к сети **только** в этих случаях:

- **Получение подписки.** HTTP(S)-запрос к URL подписки, который вы
  вписали сами. Что именно отправляется — см. раздел «Заголовки»
  ниже; `x-hwid` по умолчанию выключен и появляется только после явного opt-in.
- **Обновления приложения.** In-app updater отключён и не делает
  сетевых запросов. Релизы скачиваются и устанавливаются вручную.
- **Скачивание geofiles.** Только при включенном split-routing —
  загружается `geoip.dat`/`geosite.dat` с GitHub Releases
  (`Loyalsoldier/v2ray-rules-dat`), хеши `.sha256` проверяются перед
  перезаписью.
- **Routing-профили из URL.** Только для URL-источника, который
  пользователь сам импортировал и активировал. Routing-директивы из тела/заголовков
  подписки остаются pending: до подтверждения ничего не скачивается и не активируется.
- **Leak-test (опционально, по умолчанию on).** После подключения
  делаются запросы к Cloudflare `cdn-cgi/trace`, `ipwho.is` и
  DoH-запрос `whoami.cloudflare` к `1.1.1.1` через активный туннель —
  чтобы убедиться, что VPN реально работает, и показать вам внешний IP.
  Тумблер в Settings → «безопасность».
- **VPN-трафик.** Само собой, ваш сетевой трафик идёт через VPN-сервер
  выбранной подписки. Это её нормальная функция; выбор сервера и
  доверие к нему — на вашей стороне.

Никаких других серверов приложение не запрашивает. Никакой телеметрии,
crash-репортинга «домой», обновлений конфигурации с центрального
сервера, A/B-тестов, рекламы.

### 3. Системные изменения

- **Системный прокси.** В режиме *proxy* приложение записывает наши
  адреса в реестр HKCU (Internet Settings → ProxyServer/ProxyEnable).
  При отключении значения возвращаются как было; при крахе
  приложения — самовосстановление при следующем запуске.
- **WinTUN-адаптер.** В режиме *TUN* через helper-сервис создаётся
  виртуальный адаптер с точным ownership-префиксом `kwikproxy-secure-`.
  Cleanup считает принадлежащими приложению только имена с этим префиксом.
- **WFP-фильтры (Windows Filtering Platform).** Если включён kill
  switch — helper-сервис ставит фильтры брандмауэра на уровне ядра.
  Они автоматически снимаются при отключении (DYNAMIC session) и
  cleanup'ятся даже если процесс падает.
- **Helper-сервис (KwikProxy Secure Helper).** Устанавливается только
  installer'ом в защищённый per-machine каталог, работает с правами SYSTEM
  и слушает локальный named-pipe `\\.\pipe\KwikProxySecure.Helper.v13`
  с access-check'ами.

Все собственные ключи/пути изолированы namespace `KwikProxy Secure`,
`KwikProxySecure` или `kwikproxy-secure.*`. Installer и startup не мигрируют,
не удаляют и не меняют upstream/legacy сервисы или данные.

## Что приложение **не делает**

- Не отправляет ID пользователя или устройства на наши серверы
  (потому что у нас нет «наших серверов» в смысле центральной
  инфраструктуры).
- Не отслеживает и не передаёт историю посещений. Содержимое вашего
  трафика не логируется; локальный диагностический лог Mihomo
  (см. выше) остаётся на компьютере.
- Не передаёт crash-dump'ы автоматически. Они лежат локально, пока
  вы их сами не удалите или не приложите к bug-report'у.
- Не имеет remote-control механизмов. Deep-link и заголовки подписки
  имеют **строгий whitelist** — они не могут запускать процессы,
  читать файлы вне стандартных путей, отключать Settings или
  скрывать серверы.

## HWID и идентификация

Передача `x-hwid` **выключена по умолчанию**. После явного включения
клиент отправляет не Windows MachineGuid, а псевдоним, выведенный из
случайного локального секрета и нормализованной HTTPS-записи конкретной
подписки (path и query входят, fragment нет). Разные подписки получают разные
псевдонимы, поэтому провайдеры не могут связать их по общему аппаратному ID.

Вы можете снова отключить отправку или вписать отдельный override
для конкретной подписки (advanced).

## Заголовки HTTP-запроса подписки

При запросе подписки клиент отправляет:

```
User-Agent: clash-verge/v2.0.0   (или ваш override из Settings)
```

И опционально (при включенном HWID):

```
x-hwid: <псевдоним для этой HTTPS-подписки>
```

Это всё. Никаких трекеров, рефереров, fingerprint'а браузера,
версии ОС или модели устройства не передаётся.

## Третьи стороны

- **Сервер вашей подписки.** Мы не имеем к нему отношения и не несём
  ответственности за его политику конфиденциальности. Уточняйте
  у провайдера подписки.
- **GitHub** (скачивание geofiles при включённой функции). Стандартные
  access-логи GitHub. См. их собственную политику.
- **Cloudflare и ipwho.is** (leak-test, опционально). Несколько
  HTTP-запросов после подключения — только чтобы показать вам ваш
  внешний IP и проверить утечки.

Ни один из этих сервисов не получает информации, что запрос делает
*именно* ваш экземпляр приложения — уникальные идентификаторы не
передаются.
